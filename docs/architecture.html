검증된 호스트 도구를 진실 원천으로 두고, 그 위에서 사실(Event)과 판단(Alert)을 분리해 한국어로 조치를 안내하는 뷰·트리아지 계층. 아래 그림은 데이터가 어디서 들어와 어디로 나가는지, 계획된 변경이 어떻게 걸러지는지, 그리고 무엇이 호스트 밖으로 나가는지를 보여준다.

4. 왜 이 구조인가

  • 진실 원천은 하나씩. 차단은 fail2ban, 인증은 auth.log, 패키지는 dpkg, 취약점은 USN. 대시보드는 그 관찰을 해석할 뿐 두 번째 사실을 만들지 않는다.
  • 조용히 실패하지 않는다. 모든 모니터는 health 와 해결 명령을 노출한다. 읽지 못하는 파일은 "정상"이 아니라 "제한"이다.
  • 사실과 판단의 분리. 원시 이벤트는 근거로 남고, 알림만이 사람의 시간을 요구한다. 심각도는 알림에만 붙는다.
  • 호스트 로그는 안에 머문다. 한국어는 템플릿으로 만든다. 외부 API 에 나가는 것은 공개 뉴스 제목뿐이다.
  • 계획된 변경은 알림이 아니다. 패키지가 만든 cron·SUID·설정, mask 링크, snap 갱신은 소유 패키지와 최근 패키지 작업을 대조해 사실로만 남긴다. 운영자는 점검 모드로 작업 창을 선언한다. sudoers·sshd_config·authorized_keys·ld.so.preload 와 침입 신호는 예외 없이 알린다.
  • 최소 권한. root 대신 전용 계정 + 세 개의 capability + fail2ban-client 일곱 명령만 허용하는 sudoers.
