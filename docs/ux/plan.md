# 비전문가용 화면 재설계 기획

대상: 개인 작업용 PC를 본인이 관리하는 사람. 보안 지식이 없고, 물어볼 사람도 없다.
방식: 기본 화면을 쉬운 화면으로 바꾸고, 지금의 전문가용 정보는 지우지 않고 "자세히 보기"로 접는다.

---

## 1. 이 사람의 상황

하루에 이 화면을 보는 시간은 몇 초다. 그리고 **대부분의 날은 아무 일도 일어나지 않는다.**
그래서 화면이 답해야 하는 질문은 하나뿐이다 — *"지금 내가 뭘 해야 하나?"*

실패하는 방식은 셋이다.

| 실패 | 어떻게 생기나 | 설계로 막는 법 |
|---|---|---|
| 무뎌진다 | 매일 빨강·주황이 잔뜩 떠 있으면 곧 안 본다 | 할 일이 없으면 아무것도 띄우지 않는다 |
| 방치한다 | 무슨 뜻인지 몰라 미룬다 | 용어를 쓰지 않고, 조치를 버튼 하나로 만든다 |
| 망가뜨린다 | 뜻을 모르는 채 눌러서 필요한 걸 끈다 | 누르기 전에 무엇이 바뀌는지 먼저 보여준다 |

## 2. 지금 화면의 문제

패널 11개, UI 코드 1,332줄. 모두 같은 시각적 무게로 한 화면에 나열된다.

**(1) 무엇이 중요한지 알 수 없다.**
"오늘 확인할 것"과 "참고 정보"가 같은 테두리, 같은 크기로 놓여 있다.

**(2) 시스템 구조대로 나뉘어 있다.**
`모니터 상태` · `라이브 피드` · `알림` · `노출 면` · `설정 점검` — 전부 **만든 사람의 분류**다.
사용자의 관심사(지금 안전한가 / 뭘 해야 하나 / 무슨 일이 있었나)와 맞지 않는다.

**(3) 용어가 그대로 나온다.**
실제 화면 문자열: `리스닝 포트`, `루프백 전용`, `바인딩 주소`, `브루트포스`, `리버스 셸`,
`무결성`, `DEFCON 3`, `미확인 알림`, `원시 이벤트`, `포트 스캔 휴리스틱`,
`컨테이너가 게시한 포트는 호스트 방화벽으로 막히지 않아…`

**(4) 조치가 명령어 복사로 끝난다.**
터미널을 모르면 복사한 명령을 붙여넣을 곳이 없다. (권한 조치만 버튼으로 되어 있다.)

**(5) 정상일 때의 화면이 설계되지 않았다.**
아무 문제가 없어도 열한 개 패널이 그대로 떠 있다. 대부분의 날이 이 상태인데, 이때 화면이 주는 메시지가 없다.

## 3. 설계 원칙

1. **첫 화면은 한 문장으로 답한다.** 상태 한 줄이 화면에서 가장 큰 요소다.
2. **문과 열쇠의 말로 옮긴다.** 포트·바인딩·권한이 아니라, 문·자물쇠·열쇠·기록으로 말한다.
3. **할 일이 없으면 할 일 영역을 띄우지 않는다.** 빈 목록도 띄우지 않는다.
4. **조치는 버튼 하나. 누르기 전에 무엇이 바뀌는지 보여준다.** 되돌리는 법도 함께 적는다.
5. **전문 정보는 지우지 않고 접는다.** 지금 화면 전체가 "자세히 보기" 안에 그대로 살아 있다.

> 원칙 5가 중요한 이유: 이 도구의 가치는 근거를 끝까지 보여주는 데 있다.
> 쉬운 화면은 **덜 보여주는 화면이 아니라, 순서를 정해주는 화면**이다.

## 4. 용어 번역표

화면에 쓰는 말을 고정한다. 왼쪽은 앞으로 사용자 화면에 쓰지 않는다.

| 지금 쓰는 말 | 바꿀 말 | 비고 |
|---|---|---|
| 리스닝 포트 | 밖에서 들어올 수 있는 문 | 핵심 비유 |
| 0.0.0.0 에 바인딩 | 누구나 두드릴 수 있는 문 | |
| 루프백(127.0.0.1) 전용 | 이 컴퓨터 안에서만 쓰는 통로 | 조치 대상 아님 |
| 방화벽이 허용함 | 문이 열려 있음 | |
| 방화벽이 막는 중 | 문은 있지만 잠겨 있음 | |
| 판단 불가 | 잠겼는지 확인하지 못함 | 모른다는 말을 숨기지 않는다 |
| DEFCON 1 / 3 / SAFE | 지금 확인하세요 / 살펴보세요 / 이상 없음 | 3단계 유지 |
| 미확인 알림 | 아직 안 본 알림 | |
| 알림 확인(ack) | 확인했어요 | |
| 브루트포스 시도 | 비밀번호를 계속 찍어보는 시도 | |
| 리버스 셸 | 외부에서 이 컴퓨터를 조종하려는 프로그램 | |
| 파일 무결성 변경 | 중요한 설정 파일이 바뀜 | |
| world-writable | 다른 사용자가 고칠 수 있는 파일 | |
| 권한을 좁힌다 | 나만 열 수 있게 잠근다 | |
| privileged 컨테이너 | 관리자 권한으로 도는 프로그램 | |
| 미적용 보안 업데이트 | 밀린 보안 업데이트 | |
| 차단된 IP | 접근을 막은 상대 | |
| 모니터 health=degraded | 일부만 확인 중 (이유 표시) | |
| 시뮬레이션 이벤트 | 연습용 기록 | |

## 5. 정보 구조

지금의 11개 패널을 사용자의 질문 3개로 다시 묶는다.

```
초보자 모드
  홈  ─ 지금 안전한가?      상태 한 줄 + (할 일 카드) + 안심 정보 3개
      ├ 할 일 상세          무슨 일 / 왜 문제 / 어떻게 / [조치 버튼]
      ├ 기록                무슨 일이 있었나 (평문 타임라인)
      └ 자세히 보기         예전 전문가 화면 11개 패널을 접이식으로
                            (말투는 초보자 화면 그대로, 항목마다 쉬운 말 설명)

전문가 모드
  대시보드                  예전 전문가 화면 레이아웃 그대로. 한 화면에 전부.
```

### 전환은 두 종류다 — 섞지 않는다

| | 무엇이 바뀌나 | 어디에 | 기억 |
|---|---|---|---|
| **페이지 이동** | 같은 모드 안에서 자리만 옮긴다 | 홈 본문 링크(기록·자세히 보기), 하위 화면의 `← 돌아가기` | `secdash:plain-page` |
| **모드 전환** | 누구를 위한 화면인가가 바뀐다 | 어느 화면에서든 오른쪽 위, 같은 모양의 `쉬운 화면 ｜ 전문가 화면` | `secdash:mode` |

**자세히 보기는 전문가 모드가 아니다.** 예전 패널을 담았을 뿐 초보자 모드의 한 페이지다.
그래서 모드 전환기 옆이 아니라 홈 본문에, 기록 링크와 나란히 둔다. 성격이 다른 두 전환을
상단 바에 나란히 놓으면 화면 셋이 동등해 보이고, 사용자는 자기가 지금 '모드를 바꾼 것'인지
'같은 화면 안에서 옮긴 것'인지 알 수 없게 된다.

두 축은 따로 기억한다. 전문가 화면에 다녀와도 보던 페이지로 돌아온다.
할 일 상세·기록은 잠깐 들르는 곳이라 기억하지 않는다 — 거기서 새로고침하면 홈이 맞다.

**홈에 상시로 두는 것은 셋뿐이다.**

| 항목 | 표시 | 근거 데이터 |
|---|---|---|
| 밖에서 들어올 수 있는 문 | `1개 · 직접 열어두신 것` | `/api/exposure` |
| 밀린 보안 업데이트 | `없음` | `/api/host` pending_updates |
| 이번 주에 막은 접속 시도 | `23번 · 모두 실패` | `/api/blocked`, 차단 이벤트 |

'마지막 확인'은 카드가 아니라 헤더에 둔다. 모니터 개수(14가지) 같은 값은 쓰지 않는다 —
사용자에게는 쓸모가 없고, §2(2)에서 지적한 '만든 사람의 분류'가 그대로 다시 나오는 것이다.

나머지는 **할 일이 생겼을 때만** 카드로 올라온다.

## 6. 상태는 3단계

지금의 DEFCON 3단계를 그대로 쓰되 이름과 색만 바꾼다. 단계를 늘리지 않는다.

| 상태 | 화면 문구 | 색 | 사용자가 할 일 |
|---|---|---|---|
| SAFE | 이상 없음 | 차분한 녹색 | 없음 (화면을 닫아도 된다) |
| DEFCON 3 | 살펴보세요 | 노랑 | 오늘 중 확인 |
| DEFCON 1 | 지금 확인하세요 | 빨강 | 지금 |

빨강은 화면에서 **동시에 한 곳에만** 쓴다.

### '살펴보세요' 아래 한 줄은 할 일의 종류에 따라 갈라진다

단계는 셋으로 두되, 같은 '살펴보세요' 안에 성격이 다른 두 가지가 섞여 있다는 점은 문장으로 가른다.
'밀린 보안 업데이트'와 '처음 보는 곳에서 로그인 성공'이 둘 다 WARNING 으로 오는데,
뒤의 것에 "급하지는 않지만"이라고 말하면 거짓 안심을 주게 된다.

| 할 일의 종류 | 첫 화면 한 줄 |
|---|---|
| 침입 신호 (로그인·권한·영속화·무결성·스캔 후 행동) | `무슨 신호인지 한 줄. 직접 하신 일이 아니라면 오늘 바로 확인하세요.` |
| 판단하지 못한 것 (처음 보는 알림, 감시 공백) | `무슨 일인지 한 줄. 지킴이가 판단하지 못한 일이에요. 오늘 바로 확인하세요.` |
| 위생·설정 (업데이트, 파일 자물쇠, 점검 점수) | `손볼 일이 N 가지 있어요. 급하지는 않지만 오늘 중에 해두는 게 좋아요.` |

규칙 → 종류 분류는 `frontend/src/plain/tasks.js` 의 `urgencyOf` 에 규칙 사전과 나란히 둔다.
**목록에 없는 규칙은 '판단하지 못한 것'으로 올라간다** — 처음 보는 알림을 조용히
'급하지 않음'으로 만드는 것이 이 화면의 가장 나쁜 실패이기 때문이다.
할 일 카드 순서도 같은 기준을 쓴다(긴급 → 침입 신호 → 판단 못 한 것 → 위생).

단계 이름과 색은 그대로다. 이 화면에서는 DEFCON 같은 단계 이름을 쓰지 않는다.

## 7. 조치 방식

이미 만든 권한 일괄 조치(미리보기 → 적용)를 모든 조치의 기본형으로 삼는다.

```
[ 무엇이 바뀌는지 먼저 ]        [ 적용 ] [ 나중에 ]
   전  →  후 를 그대로 보여줌
```

조치를 세 종류로 나눈다.

| 종류 | 예 | 화면 |
|---|---|---|
| 바로 됨 | 파일 잠그기, 접근 막기 | 버튼 하나 + 미리보기 |
| 컴퓨터 재시작 등이 필요 | 보안 업데이트 적용 | 버튼 + "이만큼 걸려요" |
| 사람이 판단해야 함 | 낯선 곳에서 로그인 성공 | 고치는 버튼은 없다. 본인 여부만 묻고, 아니라면 순서대로 할 일을 안내 |

명령어 복사는 기본적으로 **자세히 보기 안에만** 남긴다.

### 예외: 홈의 '지금 할 수 있는 것' (2026-09-16 결정)

USB 저장장치 차단 해제와 계정 잠금은 자주 쓸 수 있는데도 경로가 가장 길었다 —
홈 → 자세히 보기 → 항목 펼치기, 세 걸음이었다. 배치 세 가지를 목업으로 비교해
홈 아래 한 묶음으로 올리기로 정했다(세 걸음 → 한 걸음).

그래서 홈에서도 명령어 복사를 쓴다. 대신 조건을 둔다.

- **줄은 최대 셋.** 더 늘어나면 홈이 목록이 되고, '이상 없음'인 날의 여백이 사라진다.
- **버튼이 하는 일을 그대로 말한다.** 이 조작들은 root 권한이 필요하고 지킴이는 그 권한이 없다.
  그래서 버튼은 실행하지 않고 명령을 보여준다 — 묶음 제목 옆에 "누르면 터미널에 붙여 넣을
  명령을 알려드려요"라고 적는다.
- **누르기 전에 무엇이 바뀌는지 한 줄.** 이것이 홈에 올리는 대가다. 조작 수를 줄이는 것보다
  결과를 먼저 알려주는 것이 이 화면에서는 더 중요하다.
- **모르면 그리지 않는다.** 상태를 못 읽었거나 기준 시각을 모르면 그 줄을 빼고, 빈 줄로
  '할 수 있는 일이 없다'고 말하지 않는다.

눌러서 바로 실행하는 방식은 아직 하지 않는다. sudoers 에 `modprobe`·`usermod` 를 더해야
하고, 그만큼 서비스 계정의 권한이 커진다. 권한 조치처럼 대상을 지킴이가 직접 다시 스캔해
정하는 형태라면 그때 다시 본다.

## 8. 목업으로 만들 화면

1. **홈 — 이상 없음** (가장 흔한 상태. 이 화면이 제일 중요하다)
2. **홈 — 할 일 1건**
3. **할 일 상세 — 파일 잠그기** (미리보기 → 적용)
4. **조치 완료**
5. **할 일 상세 — 사람이 판단할 것** (버튼 없는 유형)
6. **기록** (평문 타임라인)
7. **자세히 보기** (전문가 화면이 접혀 있다가 펼쳐지는 모습)
8. **좁은 화면(모바일)** — 홈

## 9. 이번 작업에서 하지 않는 것

- 백엔드 API 변경 (현재 엔드포인트로 전부 구성 가능하다)
- 알림 규칙·심각도 판정 로직 변경
- 전문가 화면의 내용 삭제 (접기만 한다)
