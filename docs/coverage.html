security-dashboard · v1.0.0 · 2026-09-09

방어 범위: 무엇을 막고, 무엇을 알리고, 무엇을 못 보는가

이 시스템은 차단보다 탐지와 트리아지가 본업이다. 실제로 막는 것은 fail2ban 과 harden.sh 가 적용한 설정이고, 나머지는 일어난 사실을 근거와 함께 사람에게 빨리 알리는 것이다. 아래 표는 공격 패턴을 그 기준으로 정직하게 나눈 것이며, 기대치를 팀이 공유하기 위한 문서다.

1. 차단·예방되는 패턴

공격이 성립하지 않거나 자동으로 끊긴다. 운영자 개입이 필요 없다.

공격 패턴수준무엇이 막는가한계
SSH 비밀번호 브루트포스, 사전 공격차단fail2ban(3회 실패 차단, 재범 시 최대 1주), recidive jail, MaxAuthTries 3분산 소스에서 IP당 두어 번씩 시도하는 저속 공격은 임계 아래로 지나감. 대시보드는 계정 기준 집계로 경고는 함
잠긴·미사용 계정으로 로그인차단미사용 계정 잠금+만료, 퇴직 계정 삭제. 계정 상태 패널활성 관리자 계정의 자격증명 유출은 막지 못함
콘솔에서 GRUB 편집으로 single-user 진입차단GRUB 비밀번호 (기본 항목은 unrestricted)디스크 탈거, Live USB 부팅은 못 막음 → 전체 디스크 암호화, BIOS 비밀번호
USB 저장장치로 데이터 반출·악성 파일 반입차단usb-storage 모듈 차단 (해제 시 auditd 가 모듈 로드 기록)키보드로 위장한 USB(HID 주입)는 저장장치가 아니라 대상 아님
미사용 프로토콜(dccp/sctp/rds/tipc) 커널 취약점차단modprobe 차단사용 중인 프로토콜의 취약점은 해당 없음
코어 덤프에서 비밀 추출차단코어 덤프 비활성화—
다른 사용자 홈 열람, 느슨한 파일 권한차단홈 750, umask 027, crontab·sshd_config·grub.cfg 600, cron 디렉터리 700이미 root 면 무의미
알려진 취약점을 노린 공격예방unattended-upgrades 자동 보안 패치, USN ↔ 설치 버전 대조 알림, 미적용 업데이트 알림공개 후 패치까지의 창(zero-day)은 열려 있음
ICMP 리다이렉트, 소스 라우팅, SYN flood 일부차단sysctl 강화DDoS 자체는 막지 못함

2. 탐지되어 알림이 올라오는 패턴

대시보드가 알림과 "지금 할 일"을 만들고, 대응은 운영자가 한다. 등급은 알림 심각도다.

공격 패턴등급탐지 방법놓치는 경우
브루트포스 뒤 로그인 성공긴급같은 IP 의 실패 이력 + 로그인 성공 (AuthLogWatcher)다른 IP 로 실패한 뒤 새 IP 로 성공하면 "새 IP 로그인" 경고로만
탈취한 자격증명으로 접속경고처음 보는 공인 IP 로그인, root 직접 로그인이미 알려진 IP(사무실, VPN)에서의 접속은 정상으로 보임
리버스 셸, 바인드 셸긴급/경고셸의 stdin/stdout 이 소켓(ProcessAudit 30초), 새 리스닝 포트(NetworkWatcher)30초 안에 끝나는 셸, 소켓을 직접 잡지 않는 파이썬 C2
임시 디렉터리에서 페이로드 실행경고/긴급auditd execve 즉시, /tmp·/dev/shm 실행 파일 (root 면 긴급)홈이나 /var 아래에서 실행, 인터프리터에 -c 로 넘긴 코드
지속성: cron, systemd, SUID, authorized_keys, sudoers, ld.so.preload, 커널 모듈, 계정·그룹 추가경고/긴급무결성 diff, 영속화 스캔(5분), auditd 파일 쓰기 주체, auth.log 계정 변경(usermod·gpasswd, 추가/제거 구분)at 작업, 새 사용자 홈의 systemd user 유닛은 다음 주기
의도하지 않은 포트 노출 (전체 인터페이스 바인딩, 방화벽 허용)경고ExposureMonitor(5분)가 현재 리스너 전체를 방화벽 규칙과 대조. '변화'가 아니라 '상태'라 기동 전부터 열려 있던 포트도 잡는다방화벽을 읽을 권한이 없으면 '판단 불가'로 표시하고 안전하다고 단정하지 않음. 컨테이너 게시 포트는 아래 항목이 담당
세션 탈취용 파일 권한 (world-writable ~/.config·셸 rc·gitconfig, 노출된 개인키)경고/긴급PermissionMonitor(15분)가 홈 설정과 /etc 를 훑는다. autostart 항목·gitconfig 훅 경로를 확인해 '이미 심어졌는지'를 알림 근거로 첨부여기서 다루지 않는 경로에 심으면 놓친다. SUID/SGID 는 영속화 스캔이 별도로 담당
컨테이너 설정으로 인한 호스트 장악·방화벽 우회경고/긴급ContainerAudit(10분)가 privileged, docker.sock 마운트, 0.0.0.0 게시, host network/pid, 위험 케이퍼빌리티를 점검설정만 본다. 컨테이너 안에서 벌어지는 일은 아래 3절 그대로
권한 상승 시도경고/긴급sudo 실패, su, sudoers 변경, 새 SUID커널 취약점으로 곧장 root 가 되면 시도는 안 보이고 사후 흔적만
내부 정찰 (nmap, masscan, hydra, tcpdump …)경고실행 파일명 정확 일치 (auditd + 샘플링)이름을 바꾼 바이너리, 파이썬으로 짠 스캐너
방어 도구 제거긴급fail2ban·openssh·auditd 등 패키지 제거 이벤트 + 누가 실행했는지서비스 중지만 하면 모니터 health 가 "제한"으로 바뀌지만 알림은 아님
크립토마이너, 포크 폭탄경고CPU 지속 90%, 프로세스 급증, 상위 프로세스 첨부CPU 를 낮게 쓰는 마이너
시간 조작으로 로그 교란경고NTP 동기화 끊김 (timedatectl)—
서비스 중지 중 파일 변조긴급시작 시 DB 기준선과 비교변조 후 기준선 DB 까지 바꾸면 못 잡음 (root 필요)
아웃바운드 C2 연결정보만처음 보는 외부 IP 연결에 프로세스명 첨부 (라이브 피드)알림이 아님. HTTPS 로 클라우드에 비콘하면 정상 트래픽과 구분 불가

3. 방어도 탐지도 못 하는 패턴

설계 범위 밖이거나 호스트 안에서는 볼 수 없는 것. "부분"은 사후 흔적만 잡히는 경우다.

공격 패턴수준이유메우려면
웹 애플리케이션 공격 (SQLi, RCE, 업로드 취약점)불가애플리케이션 로그를 보지 않음. 셸이 떨어진 뒤 흔적만 잡음앱 로그 소스 추가, WAF
컨테이너 내부에서 벌어지는 공격 (docker)불가auditd 규칙이 대화형 세션만 기록해 컨테이너 프로세스 제외. /proc 스캔은 보지만 컨텍스트 없음. 컨테이너 설정은 2절에서 점검하지만, 그 안에서 실행되는 것은 보지 못한다컨테이너용 audit 규칙, Falco 같은 런타임 보안
권한 있는 사용자의 데이터 반출 (SSH·HTTPS 로 파일 복사)불가유출 감시(DLP)와 전송량 분석이 없음이그레스 필터링, 전송량 기준 알림
파일리스·메모리 상주 공격부분디스크에 남지 않으면 무결성·SUID 스캔 무력. execve 에 python -c … 로만 남음메모리 포렌식, EDR
커널 루트킷부분/proc 을 속이면 프로세스·소켓 감시가 모두 속음. 모듈 로드 알림이 마지막 기회Secure Boot, 모듈 서명 강제, 부팅 무결성 측정
제로데이 커널·sshd 취약점불가패치가 없음. 성공 뒤 지속성 단계에서만 탐지노출 면 축소 (키 인증만, 포트 노출 최소화)
공급망: 악성 pip/npm/.deb 패키지부분설치 이벤트는 남지만 정상 설치와 구분 못 함패키지 서명 검증, 사설 미러, SBOM 대조
피싱·소셜 엔지니어링으로 관리자 자격 획득불가호스트 밖의 사건. 새 IP 로그인 경고가 유일한 신호하드웨어 키 2단계 인증
네트워크 계층 공격 (ARP 스푸핑, MITM, DDoS)불가호스트 소켓 테이블만 봄네트워크 IDS, 상위 방화벽
물리 공격: 디스크 탈거, 콜드부트불가부팅 이후만 감시전체 디스크 암호화, TPM
root 획득 이후의 흔적 삭제부분로그·DB·알림 모두 로컬. Slack 에 이미 나간 알림만 남음외부 로그 호스트 (Lynis LOGG-2154)
대시보드 자체 정지불가secdash 를 죽이면 아무도 알리지 않음 (재시작은 실패 시에만)외부 헬스체크(dead man's switch), 주기 하트비트

4. 경계선과 다음 조치

이 시스템의 가치는 공격자가 root 를 얻기 전, 또는 얻는 순간의 흔적을 사람에게 보내는 것에 있다. root 를 얻은 뒤에는 호스트 안의 모든 감시(로그, DB, 모니터, auditd)가 조작될 수 있다. 그 이후를 위한 유일한 방어는 호스트 밖에 있다.

  • 외부 로그 호스트. rsyslog 로 auth.log 와 audit 로그를 다른 호스트에 전송한다(Lynis LOGG-2154). root 를 얻은 공격자가 흔적을 지워도 사본이 남는다. 설정 한 줄, 가장 값싸다.
  • 대시보드 하트비트. secdash 가 주기적으로 외부(Slack 또는 감시 서버)에 살아 있음을 알리고, 끊기면 그쪽에서 경보한다. 지금은 서비스를 죽이면 조용해진다.
  • SSH 키 인증 전용. PasswordAuthentication no. 브루트포스 표면이 사라지고 fail2ban 은 보험이 된다. 모든 관리자 키가 등록된 뒤에 적용한다.
  • 전체 디스크 암호화. 물리 접근이 가능한 서버에서 GRUB 비밀번호는 절반이다. 디스크를 뽑아 가면 나머지 절반이 필요하다.
  • 애플리케이션·컨테이너 가시성. 이 서버가 웹 서비스나 컨테이너를 운영하게 되면 그 로그를 소스로 추가해야 3절의 첫 두 줄이 2절로 올라온다.
